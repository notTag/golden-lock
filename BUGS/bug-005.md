# [005] unlock from a real root shell restores ownership to 0:0 instead of a usable user

- Status: open
- Created: 2026-06-12
- Severity: low
- Bump: patch

## Repro
1. Become root directly (e.g. `sudo -i` or a root login), NOT via
   `sudo golden-test ...`, so `SUDO_UID`/`SUDO_GID` are unset.
2. Run `golden-test unlock <file>`.

## Expected
After unlock the file is writable by a normal user so it can be edited/removed
without further privilege.

## Actual
`SudoUID` (permissions.go:41-55) falls back to `os.Getuid()`/`os.Getgid()` when
`SUDO_UID`/`SUDO_GID` are absent. In a real root shell that is `0:0`, so
`UnlockFileFD` chowns the file to root:0 and chmods 0644 — owner-writable only
by root. The file is "unlocked" in mode but still root-owned, so an ordinary
user still cannot modify it.

## Notes
Minor edge case; the normal `sudo golden-test unlock` flow is unaffected because
sudo sets `SUDO_UID`/`SUDO_GID`. Consider warning when run as root without
`SUDO_UID`, or requiring an explicit `--uid` in that situation, so unlock
doesn't silently leave a root-owned artifact.
