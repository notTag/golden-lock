# [008] verify conflates manifest IO/permission errors with an absent manifest (exit 3)

- Status: open
- Created: 2026-06-12
- Severity: low
- Bump: patch

## Repro
1. Make `golden-test.lock` present and intact but unreadable to the verifying
   user (e.g. mode 000, or a directory permission that yields EACCES).
2. Run `golden-test verify`.

## Expected
An intact-but-unreadable manifest is distinguishable from a genuinely
absent/malformed one, so the operator can tell "I can't read the trust anchor"
apart from "there is no trust anchor."

## Actual
`Verify` (verify.go:45-49) maps every error from `ReadManifest` to
`ExitVerifyLockfile` (exit 3, "absent or malformed"), including EACCES and other
IO errors. An unreadable-but-present manifest reports identically to a missing
one.

## Notes
Mostly cosmetic — CI treats any non-zero verify exit as failure either way — but
the diagnostic is misleading. Optional fix: detect non-NotExist/non-malformed
errors and surface a distinct message (or a separate exit code) so operators
aren't told the manifest is gone when it is merely unreadable.
