# [009] Repo-root selection trusts path-based markers (documented residual)

- Status: open
- Created: 2026-06-12
- Severity: low
- Bump: patch

## Repro
1. In a location the unprivileged agent controls, plant a `.git` entry or a
   `golden-test.lock` marker.
2. Run a golden-test command whose discovery walk reaches that directory before
   the intended root.

## Expected
The directory chosen as the repo root cannot be steered by an attacker who can
only plant marker files.

## Actual
`FindRepoRoot` uses path-based `os.Stat` to detect the `.git` / `golden-test.lock`
markers (lockfile.go:92-97), so an attacker who can plant such a marker may
influence WHICH directory is selected as the root. This is the residual already
documented in ARCH.md:168-175. Crucially it cannot induce a symlink-follow (the
chosen root is still opened through the O_NOFOLLOW canonical walk) and cannot
launder a root-owned 0444 hash (chown still targets the real inode); at worst it
selects a different legitimate directory the attacker already controls.

## Notes
Logged for completeness; accepted as a known residual, not a new defect. A
future explicit `--lockfile`/`--root` flag would sidestep discovery entirely
(see bug-003, which shares this fix). Keep or close per your call.
